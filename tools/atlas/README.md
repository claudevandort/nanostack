# nanostack project atlas

A static-HTML, read-only view of the project state — services, ops, cross-service wiring, version trajectory, conformance counts, perf baseline.

The atlas is **derived** from the canonical docs (`docs/SUPPORT.md`, `docs/CHANGELOG.md`, `docs/PRD.md`, `docs/COVERAGE.md`, `docs/BENCH.md`, `CLAUDE.md`). There is no separate source of truth — if the atlas and the docs drift, rerun the builder.

## View it

```sh
# From the repo root:
python3 -m http.server --directory tools/atlas 8765
# Then open http://127.0.0.1:8765/
```

You can also `file://` it directly — most browsers will block `fetch('./data.json')` from a `file://` URL, so the http.server route is recommended.

## Refresh it

```sh
python3 tools/atlas/build.py
```

This re-parses the canonical docs and rewrites `tools/atlas/data.json`. The HTML reads `data.json` on load — no build step, no bundler.

## What's on screen

- **Hero**: current version, the project tagline (extracted from `CLAUDE.md`), and headline tiles (service count, total ops, S3 Smithy coverage, test counts per SDK).
- **Service surface**: the four service columns (S3 / DynamoDB / SQS / SNS). Each op row is colored by its enforcement category (left border):
  - **enforced** — the row explicitly calls out request-time enforcement (e.g. policy eval).
  - **supported** — implemented and works against real SDK clients.
  - **accept-store-roundtrip** — accepted, stored, returned; not semantically enforced.
  - **partial / not supported / unknown** — should be self-explanatory.
  - Hover an op for the verbatim SUPPORT.md status; click the service header for the documented divergences.
- **Cross-service wiring**: SVG diagram of the five services + the flows between them. Solid lines for supported flows, dashed for not-yet-wired. Click a flow for the divergence notes.
- **Version trajectory**: pills for every release in `docs/PRD.md §15`. Shipped versions in green, planned versions dashed-amber. Click a pill for the release summary + conformance numbers after that release.
- **Performance baseline**: tiles from `docs/BENCH.md`'s "Current baseline" table.

## How the data flows

```
CLAUDE.md ──► tagline + version
docs/SUPPORT.md ─► services[*].ops, services[*].divergences, cross_service.flows, wedge
docs/CHANGELOG.md ─► test counts per version, release headlines
docs/PRD.md §15 ─► timeline entries (shipped/planned + scope + rationale)
docs/COVERAGE.md ─► S3 Smithy headline (covered / total)
docs/BENCH.md ─► perf baseline metrics

→ tools/atlas/build.py
    → tools/atlas/data.json
        → tools/atlas/index.html (fetched by atlas.js)
```

## Accessibility notes

- **No flashing or blinking** — transitions are capped at 150ms ease-out, no animations on load.
- **Theme toggle** (top-right) persists in `localStorage`. Auto-detects `prefers-color-scheme: dark`.
- **Keyboard**: `Esc` closes the side panel; focus rings on all interactive elements.
- **Search**: ops are text in the DOM, so `Cmd-F` / `Ctrl-F` finds any op name.

## Layout

```
tools/atlas/
├── README.md         (you are here)
├── build.py          (parses docs → data.json)
├── data.json         (committed; regenerated by build.py)
├── index.html        (single page)
├── atlas.css         (epilepsy-safe palette, no animations beyond ≤150ms fades)
└── atlas.js          (vanilla JS, no dependencies)
```
